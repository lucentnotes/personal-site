04

让设计可以交接、讨论和检查

游戏、叙事和动画分工推进。我用材料与检查节点，让大家围绕同一个设计协作。

01

交接：让同伴独立理解设计

没有额外长会的时间，我提供可试玩 HTML、带流程图的机制说明和完整截图指南。说明叙事需要达到的效果，把具体内容留给叙事同伴。

02

审阅：先整理问题，再决定怎么改

提前记录问题画面、说明与建议方案。建议作为讨论起点，由不同分工共同判断，再明确修改任务。

03

交付：把单项检查和整体检查分开

先审阅单项预览，再合并试玩，最后做在线与外部体验检查。交付准备备用链接和本地 HTML 版本。

单项预览 → 审阅确认 → 合并 → 整体试玩 → 在线测试 → 外部体验 → 发布

展开设计依据与取舍

设计依据

按组合的关注重点组织反馈，用于区分衡量体系，而不是给玩家选择排等级。

回看这一决定

18 种混合组合被归入同一类。这保留了清楚的分类结构，但不同组合之间的差异是否值得进一步呈现，仍值得检视。

路径如何分支

根据首次分配安排不同任务，让不同起点都能形成有意义的比较。

首次接近均等↓

制造明显差异

首次差距明显↓

尝试重新平衡

↓ 共同目的：观察并比较不同权重状态

展开设计依据与取舍

路径服务于比较，不把均衡权重规定为正确答案。

查看当时的路径条件

首次判断：最高与最低权重相差不超过 5 个百分点时，视为接近均等。

接近均等时，第二次分配需要制造至少 20 个百分点的差距；首次不均等时，第二次需要缩小原有差距。

重新平衡后仍未接近均等时，系统提供 34 / 33 / 33 作为参照；已经形成所需对比时，则进入比较。

使用的工具与技术

以下聚焦我负责的 Game 部分：从设计讨论、界面与交互，到检查和交付。

ChatGPT / Codex
我用 ChatGPT 讨论机制与操作逻辑，用 Codex 推进原型和代码实现。我组织需求、提供参照、比较方案并审阅结果；AI 协助提出方案、整理材料、编写代码与检查。
React / TypeScript / HTML / CSS / Vite
Game 的界面与交互基于 React、TypeScript 和网页技术实现，使用 Vite 开发与构建。Codex 编写实现；我定义并检查指标选择、权重确认、条件分支与结果展示。
Web Audio API
用于交互音效的生成与播放。Codex 实现音效逻辑；我提出声音反馈需求，并通过预览检查音量、触发时机和体验。
Git / GitHub
保存版本、共享源文件并整合不同成员的工作。我明确合并范围与交付要求，通过预览审阅后再更新正式版本。
Playwright / Chromium
Codex 执行浏览器检查，核对文案、布局、交互逻辑、动画衔接和音效，并生成截图。我结合预览与试玩继续提出修改。
Padlet
承接 Design Lab 的讨论。我准备问题、辅助说明和示例内容，再将官方看板嵌入代码交给 Codex 接入游戏。
Cloudflare Pages / itch.io
托管游戏并提供可分享的体验链接，同时准备可下载的本地 HTML 版本用于备用交付。
